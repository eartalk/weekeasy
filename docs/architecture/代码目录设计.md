# 代码目录设计

## 1. 仓库结构

```text
weekeasy/
├─ apps/
│  ├─ web/                   # Next.js 用户端与管理端
│  ├─ api/                   # NestJS API
│  └─ worker/                # AI 和通知异步任务
├─ packages/
│  ├─ bazi-core/             # 无框架依赖的命盘领域模型
│  ├─ bazi-calendar/         # 历法、时区和真太阳时适配
│  ├─ rule-engine/           # 规则、权重和冲突处理
│  ├─ assessment-core/       # Big Five 计分
│  ├─ analysis-core/         # 跨模型比较
│  ├─ report-contracts/      # AI 报告 Schema
│  ├─ api-contracts/         # API 请求响应 Schema
│  ├─ ui/                    # 公共 UI
│  ├─ observability/         # 日志、追踪和脱敏
│  └─ config/                # TS、ESLint 等配置
├─ database/
│  ├─ prisma/
│  ├─ migrations/
│  └─ seeds/
├─ tests/
│  ├─ golden/                # 排盘黄金用例
│  ├─ fixtures/
│  └─ e2e/
├─ docs/
├─ tooling/
├─ docker-compose.yml
├─ pnpm-workspace.yaml
└─ turbo.json
```

## 2. Web 目录

```text
apps/web/src/
├─ app/
│  ├─ (marketing)/
│  ├─ (auth)/
│  ├─ (product)/
│  ├─ share/reports/[shareToken]/
│  └─ admin/
├─ features/
│  ├─ auth/
│  ├─ profiles/
│  ├─ birth-input/
│  ├─ chart/
│  ├─ assessment/
│  ├─ report/
│  ├─ feedback/
│  └─ admin/
├─ components/
├─ lib/
├─ hooks/
└─ styles/
```

`app/` 负责路由、布局和页面级数据获取；`features/` 负责具体产品能力。只有真正跨功能复用的组件进入公共 `components/`。

│  ├─ assessments/

复杂业务模块使用：

```text
module/
├─ domain/
├─ application/
├─ infrastructure/
├─ presentation/
└─ module.ts
```

简单 CRUD 模块不强制创建空的 DDD 分层，避免过度设计。

## 4. Worker 目录

```text
apps/worker/src/
├─ main.ts
├─ processors/
│  ├─ report-generation.processor.ts
│  ├─ notification.processor.ts
│  └─ data-export.processor.ts
├─ services/
│  ├─ report-generation.service.ts
│  ├─ report-validation.service.ts
│  └─ content-safety.service.ts
└─ infrastructure/
   ├─ ai/
   ├─ database/
   └─ queue/
```

Worker 不暴露公开业务 API，只消费任务、调用外部服务、校验输出和保存结果。

## 5. 核心包约束

`bazi-core`、`rule-engine`、`assessment-core` 和 `analysis-core` 禁止依赖：

- NestJS；
- Next.js；
- Prisma；
- Redis；
- OpenAI SDK；
- HTTP；
- 环境变量。

这些包必须可以用纯单元测试运行。

## 6. 命名规则

- 文件名使用 kebab-case；
- TypeScript 类型和类使用 PascalCase；
- 数据库表和列使用 snake_case；
- 稳定业务代码使用大写 snake case，例如 `BIG_FIVE_SHORT`；
- API 字段统一使用 camelCase；
- 领域实体不得直接作为 API DTO 返回。
