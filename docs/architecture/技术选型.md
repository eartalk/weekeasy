# 技术选型

## 1. 总体方案

```text
Next.js Web
    ↓ REST API
NestJS 模块化单体
    ↓
PostgreSQL / Redis
    ↓ BullMQ
AI Worker
    ↓
LLM Provider
```

项目采用全 TypeScript 技术栈，运行时组件独立，代码统一放在 Monorepo 中管理。

## 3. 架构方式

第一版使用模块化单体，不拆微服务：

- Web、API、Worker 是独立运行进程；
- API 内的业务能力按照模块隔离；
- 排盘、规则、测评和分析是无框架依赖的独立 package；
- 外部邮件、AI、存储和地图服务通过接口适配；
- 将来有明确规模需求时再拆服务。

## 4. 排盘与 AI 的职责边界

```text
代码：时间处理、历法计算、四柱排盘
规则：结构判断、维度评分、证据和冲突
AI：解释、组织、改写和生成行动建议
```

AI 不得：

- 自行计算四柱；
- 修改命盘；
- 虚构规则证据；
- 绕过结构化输入读取全部用户资料；
- 直接决定用户是否具有某种医学或心理问题。

## 5. 部署策略

### 开发环境

Docker Compose 提供：

- PostgreSQL；
- Redis；
- Mailpit；
- 可选 MinIO。

Web、API、Worker 在本地分别启动，保留热更新。

### MVP 环境

- Web 独立部署；
- NestJS API 独立部署；
- Worker 作为无公网入口的后台进程；
- 使用托管 PostgreSQL 和 Redis；
- 暂不使用 Kubernetes。
