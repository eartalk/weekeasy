# 安全与隐私方案

## 1. 数据分类

### 高敏感数据

- 出生日期和时间；
- 出生地点和经纬度；
- 邮箱；
- 心理测评答案；
- 用户自由文本反馈；
- 报告内容。

### 凭证与密钥

- 邮箱验证码；
- Session Token；
- Refresh Token；
- 分享令牌；
- OpenAI、Resend、数据库和存储密钥。

凭证与密钥不得以明文写入数据库日志或错误追踪。

## 2. 最小化原则

- AI 不接收姓名、邮箱或账户 ID；
- AI 优先接收标准化命盘、维度、证据和测评分数；
- 分享页面不显示精确出生信息；
- 日志不记录完整出生资料；
- 不为了运营分析复制敏感数据；
- 不使用出生资料构建广告标签。

## 3. 存储保护

- 生产数据库启用传输和静态加密；
- 出生资料上线前启用应用层字段加密；
- Token、验证码和分享令牌仅保存哈希；
- `input_hash` 使用带密钥 HMAC，避免通过枚举反推出生时间；
- 管理端默认展示脱敏邮箱和地点；
- 密钥通过部署平台 Secret 管理，不提交 Git。

## 4. 权限控制

- 每次访问 Profile、命盘、测评和报告都验证所有权；
- 管理员权限与普通用户权限分离；
- 管理员查看敏感信息必须产生审计记录；
- Worker 只获得生成报告所需的最小数据；
- 数据库账户按 Web、API、Worker 的需要限制权限。

## 5. 分享安全

- 分享默认关闭；
- 用户主动创建分享链接；
- 分享令牌使用高强度随机值；
- 数据库只保存令牌哈希；
- 支持设置到期时间；
- 支持随时撤销；
- 分享内容应用独立脱敏策略。

## 6. 删除与注销

- 档案删除后立即停止正常访问并撤销分享；
- 冷静期结束后物理删除关联出生资料、命盘、测评、分析、报告和反馈；
- 注销时撤销所有 Session；
- 审计记录只保留最小匿名事件，不保留可恢复的个人资料；
- 具体冷静期和保留期限由上线地区的法律与隐私政策确定。

## 7. AI 安全边界

- AI 输出必须通过 JSON Schema；
- 对确定性、灾难性、医疗和投资措辞执行内容审查；
- AI 失败不能影响命盘和测评结果；
- 保存模型、Prompt 和 Schema 版本；
- 不默认长期保存包含敏感信息的完整原始 Prompt；
- 用户报告明确标注传统文化解释和非诊断声明。

## 8. 上线前安全清单

- 配置 CSP、HTTPS、安全 Cookie 和 CORS；
- 登录、报告生成和分享接口启用限流；
- 防止用户枚举邮箱；
- 检查所有日志脱敏；
- 校验对象级权限；
- 建立数据库备份和恢复演练；
- 建立依赖漏洞扫描；
- 建立密钥轮换流程；
- 完成隐私政策、用户协议和注销流程。
