# Monorepo 架构

## 1. 定义

Monorepo 是代码仓库组织方式，不是前后端运行方式。

本项目仍然采用前后端分离：

```text
浏览器
  ↓ HTTP
Next.js Web
  ↓ REST API
NestJS API
  ↓ Queue
AI Worker
```

区别只是 Web、API、Worker 和公共业务包统一放在一个 Git 仓库。

## 2. 与传统多仓库的区别

传统多仓库：

```text
weekeasy-web      独立 Git 仓库
weekeasy-api      独立 Git 仓库
weekeasy-worker   独立 Git 仓库
```

本项目 Monorepo：

```text
weekeasy/
├─ apps/web
├─ apps/api
├─ apps/worker
└─ packages/*
```

两种方式都可以前后端分离和独立部署。

## 3. 选择 Monorepo 的原因

- 早期个人或小团队协作成本更低；
- 前端、API 和 Worker 可以共享接口契约；
- 排盘核心和规则引擎无需单独发布 npm；
- 一次提交可以完整修改数据库、API、Worker 和前端；
- 统一 TypeScript、Lint、测试和构建配置；
- 保留未来将 package 独立发布或服务拆分的能力。

## 4. 共享边界

允许共享：

- API 请求和响应 Schema；
- 报告 JSON Schema；
- 无框架依赖的排盘核心；
- 规则引擎；
- Big Five 计分；
- UI 基础组件；
- ESLint 和 TypeScript 配置。

禁止共享：

- Prisma 数据库实体到前端；
- NestJS Service 到 Web；
- 服务器环境变量到客户端；
- OpenAI、Resend 等密钥；
- 后端 Repository 实现。

## 5. 运行和部署

项目可以分别运行：

```text
pnpm dev:web
pnpm dev:api
pnpm dev:worker
```

也可以统一启动：

```text
pnpm dev
```

构建和部署仍然独立：

```text
pnpm build:web
pnpm build:api
pnpm build:worker
```

修改前端不要求重新部署 API；只有被修改或受依赖影响的应用需要重新构建。

## 6. 依赖方向

```text
apps/web
  → api-contracts
  → report-contracts
  → ui

apps/api
  → bazi-core
  → rule-engine
  → assessment-core
  → analysis-core

apps/worker
  → analysis-core
  → report-contracts

rule-engine → bazi-core
```

核心 package 不允许反向依赖 `apps/*`。
